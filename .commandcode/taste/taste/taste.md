# Taste
- Backend should follow Clean Architecture with separated layers (handler / service / repository / model). Confidence: 0.8
- API responses must use a standard JSON envelope: `{ "success": true, "message": "...", "data": ... }`. Confidence: 0.8
- Reads and understands all spec files in /docs before writing any code. Confidence: 0.7
- Prefers thorough, step-by-step explanations and written docs ("kasih tau yang detail dan lengkap serta mudah dipahami", "lengkap dan detail tetapi mudah dipahami") — comprehensive yet easy to follow — over terse output. Confidence: 0.7
- Works backend-only; never touches frontend/UI code (no React, HTML/CSS, or other frontend files). Confidence: 0.3 (user has since requested frontend/UI refactoring — StockList.tsx audit)
- Wants DB migrations kept minimal and separated by purpose: exactly two files, one for schema (`001_schema.sql`) and one for seed data (`002_seed.sql`) — no incremental `003_`/`004_`/`005_` files. The seed must be re-runnable for demos: it resets the data from scratch first (`TRUNCATE ... RESTART IDENTITY CASCADE`) then re-inserts, so the demo can be replayed any number of times. Confidence: 0.85
- Treats API latency as a standing quality bar, not an optional extra: expects the backend to feel near-instant ("tidak lag/load lama") and wants performance work done proactively before handing it to the frontend. Confidence: 0.65
- Prefers stock/quantity mutations to be server-computed atomic deltas (e.g. `UPDATE ... SET x = x + $1`) inside a transaction, never absolute values sent from the client; absolute writes are reserved for deliberate human corrections (e.g. stock opname) with a recorded reason. Confidence: 0.8
- Wants a human-in-the-loop gate before any irreversible/external side effect: draft artifacts must stay editable and require an explicit action (button/submit) before triggering sends or approvals — no auto-fire in the same step that creates the draft. Confidence: 0.55
- Prefers write endpoints to be idempotent and guarded against double-submission (unique constraint keys, disable the submit action while a request is pending). Confidence: 0.7
- Frontend/UI should avoid "AI slop" aesthetics and look like a polished, real B2B SaaS dashboard, while keeping the website's existing colors and brand identity unchanged. Confidence: 0.7
- After approving a proposed plan, expects the work to be carried through to a fully implemented and verified end state ("kerjakan sampai selesai/berhasil diimplementasikan") rather than stopping at a plan, partial change, or open question. Confidence: 0.6
- Wants generous vertical breathing room on app pages: content must not hug the top/bottom edges, and spacing fixes should apply uniformly across all pages (except login). Confidence: 0.55
- Pages (including login) should not look too sparse/empty ("terlalu sepi", background "terasa kosong") — user wants them visually full, alive, and rich ("lebih hidup dan bagus"), matching a professional B2B SaaS login/dashboard. Confidence: 0.7
